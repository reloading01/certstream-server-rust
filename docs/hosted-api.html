Hosted CertStream API

A hosted, CertStream-compatible WebSocket API. Get every new TLS certificate and domain name from Certificate Transparency logs in real time. Access needs an API key, from $2 a month through GitHub Sponsors.

Connect to the CertStream WebSocket

Certificates arrive as JSON text frames in the same format as the self-hosted server. Clients that support WebSocket compression (Python websockets, Node ws, browsers) receive about 5 times less data with no code change.

EndpointStreamTier
wss://api.certstream.dev/?key=KEYDomain names only (default), ~200 B per certificateStream
wss://api.certstream.dev/lite?key=KEYLite, without DER and chain, ~1 KB per certificateStream
wss://api.certstream.dev/full-stream?key=KEYFull, with DER and chainFull

Keep the key private. A client that can set headers should send Authorization: Bearer KEY instead, which keeps the key out of URLs and proxy logs.

Python
import asyncio, json, os, websockets

URL = "wss://api.certstream.dev/?key=" + os.environ["CERTSTREAM_KEY"]

async def main():
    async with websockets.connect(URL) as ws:
        async for message in ws:
            event = json.loads(message)
            if event["message_type"] == "dns_entries":
                print(event["data"])

asyncio.run(main())
JavaScript
const ws = new WebSocket("wss://api.certstream.dev/?key=YOUR_KEY");
ws.onmessage = (e) => {
  const event = JSON.parse(e.data);
  if (event.message_type === "dns_entries") console.log(event.data);
};
websocat
websocat "wss://api.certstream.dev/?key=$CERTSTREAM_KEY"

Use it with existing CertStream clients

Point a client that already speaks CertStream at the lite endpoint. Only the URL changes.

Pythoncertstream library
import certstream

def on_message(message, context):
    if message["message_type"] == "certificate_update":
        print(message["data"]["leaf_cert"]["all_domains"])

certstream.listen_for_events(on_message, url="wss://api.certstream.dev/lite?key=YOUR_KEY")

Message format

domains-only/
{
  "message_type": "dns_entries",
  "data": ["example.com", "*.example.com"]
}
lite/lite, abbreviated
{
  "message_type": "certificate_update",
  "data": {
    "update_type": "PrecertLogEntry",
    "leaf_cert": {
      "issuer": { "CN": "Amazon RSA 2048 S09" },
      "not_before": 1792405638,
      "not_after": 1796297238,
      "all_domains": ["example.com"]
    },
    "seen": 1792409244.748,
    "source": { "name": "DigiCert Sphinx2026h2" }
  }
}

Every field is described in the API documentation.

Frequently asked questions

Is the hosted CertStream API free?

No. Access needs an API key, from $2 a month through GitHub Sponsors. Running your own certstream-server-rust is free under the MIT license.

How do I get an API key?

Sponsor the project on GitHub, then sign in with the same GitHub account at api.certstream.dev/claim and press Generate API key. The key is shown once, so copy it then.

Can I use it with existing CertStream clients?

Yes. The lite stream uses the same message format as the original CertStream, so a client only needs its URL changed to wss://api.certstream.dev/lite?key=YOUR_KEY. The Python certstream library works this way.

What is the difference between domains-only and lite?

Domains-only sends just the domain names of each certificate, about 200 bytes per message. Lite adds the issuer, validity dates, fingerprints and log source, about 1 KB per message.

Which Certificate Transparency logs does it read?

The Chrome- and Apple-trusted CT logs, both RFC 6962 and static-ct-api, with certificates that appear in more than one log delivered once.

Can I get the full stream with the DER certificate and chain?

Yes, from the $10 Full tier upwards, at wss://api.certstream.dev/full-stream. You can also run your own instance of certstream-server-rust, which serves it.

What happens when I stop sponsoring?

The key stops working when the paid period ends, and a new key can be generated whenever you sponsor again.

Want to run it yourself? See the quick start or the certstream-server-rust repository.
